### 1-2. 광운대 LMS (학습관리시스템)

| 항목 | 내용 |
|------|------|
| **URL** | https://lms.kw.ac.kr |
| **크롤링 대상** | 과제 마감일, 강의 공지, 출석 정보, 시험 일정 |
| **접근 방식** | 로그인 세션 유지 후 크롤링 (requests.Session) |
| **인증 필요** | ✅ 필요 (학번 + 비밀번호) |
| **크롤링 가능 여부** | ⚠️ 조건부 가능 (사용자 로그인 정보 필요) |

**주의사항:**
- 사용자의 학번/비밀번호를 로컬에 암호화 저장 필요
- 세션 만료 시 자동 재로그인 처리 필요
- 과도한 요청 시 IP 차단 가능 → 요청 간격 조절 필수 (1~2초 딜레이 권장)

## 2. 크롤링 우선순위

```
1순위 (MVP 필수)
  ├── 광운대 공식 사이트 - 학사일정     ← 로그인 불필요, 안정적
  └── 광운대 공식 사이트 - 학사공지     ← 로그인 불필요, 안정적

2순위 (로그인 구현 후)
  ├── LMS - 과제 마감일                ← 개인화된 TODO 핵심 데이터
  └── KLAS - 수강 정보                 ← 수업 기반 일정 생성

3순위 (추후 검토)
  └── 에브리타임                       ← 이용약관 검토 필요
```

---

## 3. 크롤링 제한 및 대응 방안

| 문제 | 대응 방안 |
|------|-----------|
| IP 차단 | 요청 간 1~2초 딜레이, 재시도 로직 구현 |
| HTML 구조 변경 | 크롤러 모듈화, 파싱 로직 분리 |
| 로그인 세션 만료 | 세션 재발급 자동화, 에러 핸들링 |
| 서버 점검 | 마지막 성공 데이터 로컬 캐싱 (SQLite) |

---

## 4. 로컬 데이터 저장 구조 (예정)

```
data/
├── cache/
│   ├── schedules.json       ← 마지막 크롤링 결과 캐시
│   └── last_crawled.json    ← 크롤링 타임스탬프
├── db/
│   └── todos.db             ← SQLite (TODO 영구 저장)
└── logs/
    └── crawler.log          ← 크롤링 로그
```
